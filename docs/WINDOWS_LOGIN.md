# 직원 SEGIO 로그인으로 Windows에 DB 보관본 받기

Windows에서 **직원의 기존 SEGIO ID·암호**로 로그인하고, 서버에 준비된 해당 직원의 결재 보관본을 받습니다. 문서 페이지를 하나씩 수집하지 않습니다. ZIP 다운로드·압축 해제·파일 검증을 자동으로 수행하며, 완료 후 계정 없이 검색·열람할 수 있습니다.

**관리자가 서버에서 직원별 보관본을 먼저 준비해야 합니다.** 이 방식은 준비 시점의 DB 스냅샷을 전달합니다. Windows에서 버튼을 누를 때마다 DB를 새로 조회하는 기능은 아닙니다. 새 자료를 반영하려면 서버 준비 명령을 다시 실행합니다. 웹 프로세스에 DB 암호·sudo·셸 실행 권한을 부여하지 않기 위해 이 구조를 사용합니다.

## 서버에서 준비

최신 [segio-main.zip](https://github.com/soriel1004/segio/archive/refs/heads/main.zip)을 풀고 **`tools` 폴더 전체**를 기존 `/root/tools`에 복사합니다. 파일명만 바꿔 저장한 GitHub HTML 페이지를 실행하지 마세요. 현재 성공한 DB 추출기와 같은 설정을 사용하므로 PostgreSQL 암호나 `pg_hba.conf`를 변경하지 않습니다.

먼저 웹 서비스의 **Linux 실행 계정**을 확인합니다. 직원 SEGIO ID와는 다른 계정입니다. 아래 명령은 프로세스의 계정·실행 파일 이름만 표시합니다.

```bash
ps -eo user,comm | awk '$2 ~ /shttpd|httpd|php/ {print}'
```

업로드 배포본의 기본 Linux 계정은 `segio`입니다. 실제 실행 계정이 `segio`인 경우 `/root/tools`에서 root로 다음을 실행합니다. 다른 계정이면 `--web-user` 값만 실제 비-root 실행 계정으로 바꿉니다. root만 표시되거나 계정을 확정할 수 없다면 설치를 진행하지 말고 웹 서비스 실행 설정을 확인합니다.

```bash
cd /root/tools
python ./prepare_login_archive.py --user koro --web-user segio
```

설정 자동 검색에 실패하면 기존 추출 때 성공했던 `db.conf` 경로를 지정합니다. 설정 파일 내용이나 암호는 보내지 않습니다.

```bash
python ./prepare_login_archive.py --user koro --web-user segio \
  --config /home/segio/cell000/etc/db.conf
```

이 명령은 다음 작업을 수행합니다.

- 기존 읽기 전용 DB 추출기로 `koro`의 결재·관련 기록·첨부와 표시용 HTML을 새로 만듭니다. 본문 인코딩·Base64 서명 수정도 적용됩니다.
- 완성 ZIP과 검증 정보를 `/var/lib/segio-archive`에 root 소유로 보관합니다. 지정한 웹 실행 계정의 그룹에는 읽기·통과 권한만 부여합니다. 원래 `db.conf`·문서·DB 인증 설정의 권한은 바꾸지 않습니다.
- 해당 셀의 `folder/html/segio/archive/bridge.php`를 설치합니다. 이 파일은 로그인한 본인의 준비된 ZIP을 전달하는 기능만 제공합니다. 별도 데몬·DB 연결·서버 명령 실행은 없습니다.

`Published employee archive`가 출력되면 준비가 끝났습니다. 다른 직원은 `--user` 값만 바꿔 다시 준비합니다. 같은 직원으로 다시 실행하면 새 스냅샷을 게시하고 기존 스냅샷을 비공개 경로에 보존합니다. 디스크 사용량은 준비할 때마다 증가하므로 서버 관리자가 보존 기간을 관리해야 합니다. 이 도구가 기존 보관본이나 원본 자료를 자동 삭제하지는 않습니다.

## Windows에서 받기

1. 최신 ZIP을 Windows의 새 폴더에 풀고 **`run_windows.bat`**을 실행합니다. Python 3.12 64비트와 설치된 Edge 또는 Chrome을 사용합니다. 로그인 화면을 열 때 Chromium을 다운로드하지 않습니다.
2. 가져오기 방식을 **서버 DB 보관본 받기**로 둡니다.
3. 기존 SEGIO 로그인 주소, 직원 ID(예: `koro`), 그 직원의 SEGIO 암호, 저장 폴더를 입력합니다. DB 암호나 서버 관리자 암호는 입력하지 않습니다.
4. 현재 HTTP 주소를 사용할 경우 **암호화되지 않은 HTTP 연결 허용**을 선택합니다. 전송이 암호화되지 않으므로 신뢰하는 사내망에서 사용합니다. HTTPS 주소는 인증서 검증을 유지합니다.
5. **로그인하고 수집 시작**을 누릅니다. 프로그램이 연 임시 브라우저에서 로그인한 뒤 본인 보관본을 확인하고 내려받습니다. 직접 로그인 옵션을 사용해도 실제 로그인 ID가 입력 ID와 다르면 받지 않습니다.
6. 완료 후 **보관함 열기**에서 새 `segio-koro` 폴더를 선택합니다. 검색·본문·결재선·첨부를 확인합니다.

저장 결과는 **`segio-koro.zip`**과 압축이 풀린 **`segio-koro`** 폴더입니다. 이름이 겹치면 `-2`, `-3`을 붙여 기존 보관본을 유지합니다. 로그에는 서버 준비 시각을 한국 시간(KST)으로 표시합니다. ZIP 해시·내부 파일 해시·사용자 ID 확인이 끝나야 완료로 표시하며 실패한 임시 다운로드는 제거합니다. 로그인 암호·세션 쿠키는 보관본이나 설정 파일에 저장하지 않습니다.

메일은 방식에서 **웹 화면 수집 (결재·메일)**을 선택해 별도로 수집합니다. DB 보관본에는 메일과 자동 생성 PDF가 없습니다. 결재 HTML은 브라우저 인쇄로 PDF로 저장할 수 있습니다.

## 연결 확인과 오류

관리자는 SEGIO에 정상 로그인한 브라우저에서 다음 주소로 연결 상태를 확인할 수 있습니다. 정상 응답은 `protocol: segio-login-archive/1`, 자신의 `username`, 준비된 `archive` 정보입니다. 이 응답은 인증 상태 확인용이며 공개 상태 확인 URL이 아닙니다.

```text
http://192.168.0.100/segio/archive/bridge.php?action=info
```

| 결과 | 조치 |
| --- | --- |
| 서버 연결 기능 미설치 / 404 / HTML 응답 | 해당 셀의 실제 웹 경로와 PHP 실행 지원, 준비 명령 성공 여부 확인 |
| `native_login_required` | SEGIO가 인증한 `REMOTE_USER`가 새 PHP 경로에도 전달되는지 확인. 요청 헤더·쿼리의 ID를 인증값으로 대체하면 안 됨 |
| `identity_conflict` | SEGIO의 `$_ENV`·`$_SERVER` 인증 사용자 값이 다른 이유를 확인 |
| `insecure_php_configuration` | 레거시 `register_globals` 활성 구성에서는 연결을 거부함. 서비스 영향을 검토해 PHP 설정 조정 |
| `archive: null` / 해당 직원 보관본 미준비 | 실제 로그인한 직원 ID로 준비 명령 실행 |
| `publication_unavailable` / 파일 접근 오류 | 실제 웹 실행 계정·부모 경로 통과 권한·보안 컨텍스트 확인. `chmod 777`, 인증 해제, SELinux 전체 해제로 해결하지 않음 |
| 준비 중 같은 이름의 기존 디렉터리 거부 | 기존 파일을 덮어쓰지 않기 위한 보호. 소유자·설치 표시를 확인하거나 비공개 경로를 `--private-root`로 지정 |
| 다운로드 중 갱신·중단·해시 불일치 | 새로 로그인해 다시 받음. 미검증 ZIP을 완료 자료로 사용하지 않음 |

오류가 나면 **오류 코드만** 알려주면 됩니다. 직원 암호·쿠키·보관 ZIP·`db.conf`는 올릴 필요가 없습니다.

## 인증과 수집 범위

연결 PHP는 업로드 소스에서 사용한 `$_ENV['REMOTE_USER']` 또는 표준 CGI의 `$_SERVER['REMOTE_USER']`만 인증 사용자로 사용합니다. 빈 값·guest·충돌한 값은 거부합니다. 클라이언트가 지정한 대상 ID, `HTTP_REMOTE_USER`, `PHP_AUTH_USER`, 임의 인증 헤더를 신뢰하지 않습니다. 준비된 보관본의 사용자도 같은 ID여야 하며 다른 직원의 버전 번호만 알아서는 다운로드할 수 없습니다. DB를 조회하거나 사용자를 생성·수정·삭제하는 웹 API는 제공하지 않습니다.

보관 내용은 관리자가 승인하여 준비한 [개인 관계 기준 DB 추출 범위](DB_ARCHIVE.md)입니다. 과거 기록·댓글·즐겨찾기 등으로 관련된 문서도 포함할 수 있으므로, **관리자는 그 직원에게 제공해도 되는 범위인지 확인한 뒤 준비 명령을 실행**해야 합니다. 이는 인코딩된 SEGIO 원본의 화면별 권한 판정과 동일하다고 검증한 기능이 아닙니다. 부서 권한만으로 열리는 문서·일부 확장 업무·메일은 포함하지 않습니다.

계정 삭제 후에도 내려받은 파일을 읽을 수 있지만, 서버에서 처음 받거나 다시 받으려면 정상 SEGIO 로그인 계정이 필요합니다. 실제 서버의 인증 전달과 Windows 동작, 운영 문서 대조는 설치 후 확인해야 합니다. 보관본 생성만으로 계정 삭제 영향이 검증되는 것은 아닙니다.
