# SSH로 그룹웨어 DB·MBOX 백업 및 검색

v0.4.3부터 Windows 화면은 **관리자 SSH 접속**으로 고정합니다. 가져오기 방식 선택 항목을 제거했습니다. Windows에서 서버 SSH 계정으로 인증하고, 백업할 직원의 SEGIO ID를 별도로 지정합니다. 서버 웹페이지·PHP·직원 로그인 창을 사용하지 않습니다. SEGIO 직원 암호로 SSH에 로그인하는 방식은 아니며, 서버 관리자가 직원 자료를 백업하는 도구입니다.

## Windows에서 실행

1. **[Windows v0.4.19 직접 다운로드](https://github.com/soriel1004/segio/actions/runs/41742228924/artifacts/13282431982)**로 `SEGIOArchive-Windows`를 받습니다. GitHub 로그인 후 사용합니다. ZIP을 **한 번만 풀고** 바로 나타나는 `_internal`, `tools` 등 함께 있는 폴더를 유지한 채 `SEGIOArchive.exe`를 실행합니다. 제목의 `v0.4.19`를 확인합니다.
2. 실행하면 SSH 입력 화면이 바로 표시됩니다. 별도로 가져오기 방식을 선택하지 않습니다.
3. 아래 항목을 입력합니다.

| 입력 | 사용 서버 기준 |
| --- | --- |
| SSH 서버 주소 | `192.168.0.100` |
| SSH 포트 | `22` |
| 서버 작업 폴더 | `/backup` (v0.4.14 기본값) |
| 서버 SSH 계정 | `root` |
| SSH 암호 / 키 암호 | 서버 root의 SSH 암호. 개인키를 선택한 경우 개인키 암호 |
| 백업할 SEGIO ID | `koro` 등 직원의 실제 SEGIO ID |
| 개인키 파일 | 키 인증을 사용하는 경우에만 선택 |
| Windows 저장 폴더 | 원본 메일과 검색 DB를 저장할 디스크 |

4. **SSH 연결 확인**으로 로그인·SFTP·파일 접근을 먼저 검사할 수 있습니다. 직원 ID 없이 접속 검사만 실행할 수도 있습니다. 확인 후 **결재 문서·메일**을 선택하고 **로그인하고 수집 시작**을 누릅니다. 처음 접속할 때 표시되는 서버 지문을 아래 방법으로 확인한 뒤 저장합니다. 지문이 바뀐 서버는 자동으로 신뢰하지 않습니다.
5. 수집 후 완성된 `segio-ssh-koro` 폴더의 **index.html**을 실행합니다. 전체·결재·메일 탭에서 검색하고 본문·첨부를 바로 엽니다. 프로그램과 서버 연결 없이 열람합니다.

`root` SSH 로그인이 실제 서버에서 허용돼 있어야 합니다. 다른 관리자 SSH 계정을 사용하는 경우 그 계정이 기존 DB 설정·첨부·해당 직원 MBOX를 읽을 수 있어야 합니다. 프로그램이 root 로그인 설정·암호·sudo·PostgreSQL 인증·원본 권한을 변경하지는 않습니다.

서버 웹 연결 기능 설치는 이 방식에 필요하지 않습니다. 프로그램의 `tools`에 포함된 고정 추출 코드를 SSH로 비공개 임시 폴더에 올려 실행하므로 최신 Windows 패키지의 `tools` 폴더도 함께 유지합니다. 서버에는 기존 Python 2.6과 `psql`만 사용합니다. Windows의 SSH 라이브러리는 패키지에 포함됩니다.

## 목록·검색 화면과 보관함 열기 (v0.4.2)

**v0.4.13 인덱스 직접 삭제:** 기존 백업은 새 프로그램의 **보관함 열기**에서 폴더를 한 번 선택합니다. 이후 프로그램을 종료하고 **최신 Chrome·Edge로 index.html을 직접 열어** 삭제합니다. **페이지당 표시 오른쪽 삭제 → 현재 백업 폴더 선택·수정 허용 → 목록 앞 체크 상자 선택 → 선택한 자료 삭제 → 확인 → 백업본에서 삭제** 순서입니다. 권한이 유지되면 폴더 재선택을 생략합니다. 다른 백업 폴더는 거부합니다. **선택 취소**는 기본 화면으로 돌아갑니다. 기존 보관함 열기 방식도 유지합니다.

본문·첨부·SQLite 기록과 MBOX 내부 선택 메일을 실제 제거하고 검색·건수·검증 해시를 갱신합니다. 공유 첨부·남은 메일·서버 원본·별도 ZIP은 보존합니다. 완료된 삭제는 되돌릴 수 없습니다. 진행률·경과 시간·중단을 표시하며 최종 적용 때에는 중단할 수 없습니다. 처리 중 브라우저 탭을 유지합니다. 오류·중단 시 원래 자료를 복원하고, 비정상 종료 후에는 **같은 index.html → 삭제 → 백업 폴더 선택**으로 복구합니다. `.segio-browser-edit` 복구 폴더를 직접 삭제하지 마세요. 복구가 남으면 Windows 프로그램은 편집을 차단하고 인덱스 복구를 안내합니다.

MBOX는 1 MiB 단위로 읽지만 원본 복구 사본·새 MBOX·브라우저 임시 파일을 위한 여유 공간이 필요합니다. 확인 창은 보수적인 공간 상한을 표시하며 디스크 여유 공간은 브라우저에서 직접 조회하지 못합니다. 검색 SQLite 메타데이터는 최대 512 MiB까지 브라우저에서 처리하며 더 큰 DB는 프로그램 관리 화면에서 삭제합니다. 폴더 수정 API가 없는 브라우저는 조회 전용입니다. `viewer` 폴더의 SQLite·SHA-256 라이브러리를 포함해 전체 폴더를 함께 보관하세요. 인터넷 다운로드나 서버 설치는 삭제에 필요하지 않습니다.

**v0.4.10 날짜 정렬·표시 건수:** 전체·결재·메일을 기안일자/메일 헤더 날짜의 최신순으로 정렬합니다. 메일의 시간대 차이는 실제 시각에 반영하고, 날짜 미기록·해석 불가 자료는 마지막에 배치합니다. 시간대가 없는 날짜의 정렬 기준은 KST이며 표시 문자열은 유지합니다. 목록 위 ‘페이지당 표시’에서 25·50·75·100건을 고르거나 직접 입력란에 1~1,000건을 입력하고 ‘적용’ 또는 Enter를 누릅니다. 검색·분류 전환과 새로고침에도 표시 건수를 유지합니다. 기존 백업은 **v0.4.10 → 보관함 열기 → 백업 폴더 선택**으로 적용합니다. 이미 본문 바로보기가 준비됐다면 서버 연결이나 MBOX·첨부 재분석 없이 목록·분할 검색 자료만 갱신하며 SQLite·원본 자료는 보존합니다.

**최신 v0.4.8 화면:** 사진과 같은 표 목록으로 바뀌었습니다. 전체·결재·메일 탭 및 검색 범위 선택창을 함께 제공하며, 선택한 결재 분류·메일함 안에서 검색합니다. 결재는 완료·반려·참조·수신·진행·임시·상태 미확인 분류와 건수를 표시합니다. 표의 마지막 열에는 DB 기안일자(KST) 또는 원래 시간대를 보존한 메일 헤더 날짜를 보여주며 없는 날짜는 ‘미기록’입니다. 참조·수신 분류는 상태별 분류와 겹칠 수 있습니다. DB 원본·첨부 버튼은 목록 아래 ‘현재 목록의 원본·첨부 바로가기’, 현재/과거 필터와 수집 정보는 ‘수집 범위·검증 내역 및 추가 옵션’에서 펼칩니다. **v0.4.8 → 보관함 열기 → 기존 백업 폴더 선택**으로 새 화면을 적용합니다. 메일 바로보기가 준비된 백업은 서버 재접속·원본 MBOX·첨부 읽기 없이 DB 메타데이터로 갱신하며 원본 자료와 SQLite를 유지합니다.

백업을 열면 **결재 / 메일** 탭과 각각의 건수가 표시되며, 선택한 탭의 전체 목록을 첫 페이지부터 100건씩 볼 수 있습니다. 검색어를 입력하고 **검색** 버튼 또는 Enter를 누릅니다. **전체 목록**은 검색 조건을 지웁니다. 목록·검색창·메일 본문의 기본 글씨는 **12px**입니다. 결재 본문의 원래 서식에 지정된 글씨 크기는 유지됩니다.

이미 백업했다면 **새 v0.4.2 프로그램 → 보관함 열기 → 기존 `segio-직원ID` 폴더 선택**만 하면 됩니다. SSH 로그인이나 수집 시작은 필요하지 않습니다. Windows에 받은 원본 MBOX를 읽어 메일별 HTML·첨부를 생성하고 검색 자료·파일 해시 목록을 갱신합니다. 원본 MBOX·검색 SQLite·기존 결재 자료는 유지합니다. 중단·저장 공간 부족 시 완료한 메일을 남기고, 다음 갱신에서 해시가 일치하는 파일을 재사용합니다. 별도로 만들어 둔 ZIP은 갱신하지 않습니다.

완료 후에는 프로그램을 종료해도 **백업 폴더의 `index.html`**에서 목록·검색·결재·메일 본문·첨부를 바로 열 수 있습니다. 메일에서 ‘메일 목록’을 누르면 메일 탭으로 돌아옵니다. `search`, `mail/offline`, `mail/raw` 등 폴더 전체를 함께 보관하세요. ‘보관함 열기’ 버튼도 동일하게 기존 메일을 준비한 뒤 `index.html`을 엽니다. 새 백업은 수집 완료 전에 바로보기를 자동 생성합니다.

본문 HTML의 표·텍스트와 CID 이미지를 표시하고 외부 이미지·스크립트는 제거합니다. 첨부는 각각 원래 바이트로 저장해 직접 열거나 다운로드합니다. 텍스트 부분이 8 MiB를 넘으면 앞부분과 제한 안내를 표시하며, 전체 원본은 MBOX에 남습니다. 32 MiB를 넘는 메일도 본문과 첨부를 스트리밍 처리합니다. 바로보기 HTML·첨부가 원본 외에 추가 저장되므로 공간을 확보하세요.

명령행에서 기존 백업을 준비하는 경우:

```bash
python -m segio_archive prepare-offline "D:/SEGIO보관함/segio-ssh-koro"
```

## 메일함 분류 (v0.4.4)

메일 탭 상단에서 전체 메일·받은편지함·보낸편지함을 선택하고, **편지 보관함** 영역에서 사용자 지정 분류를 선택합니다. 각 항목에 백업된 메일 건수를 표시하며, 목록에도 **메일함** 열이 있습니다. 하위 분류는 `거래처 / 계약`처럼 표시합니다. 선택한 메일함 안에서 검색·100건 단위 페이지 이동이 가능하고, 새로고침 후에도 선택을 유지합니다. **전체 목록**은 검색어와 메일함 선택을 지웁니다.

기존 백업은 v0.4.4의 **보관함 열기**에서 선택하면 반영합니다. v0.4.2 이상으로 메일 본문이 이미 준비됐다면 MBOX·첨부를 다시 읽거나 쓰지 않고 인덱스만 갱신합니다. SQLite DB도 유지합니다. 원래 메일함 파일 이름·경로와 `sources.json`에 근거해 분류하며, 보낸 사람 주소를 보고 받은·보낸편지함을 추측하지 않습니다. 사용자 지정 이름·상하위 경로를 유지하고, 분류 정보가 없는 개별 EML은 **분류 미확인**으로 표시합니다. 원본 목록에 없는 별칭·빈 디렉터리는 새로 추측하지 않습니다.

## 기존 인덱스 표시 항목 복원 (v0.4.6)

SSH 인덱스의 간략한 제목 행을 저장소의 기존 보관함과 같은 카드형 목록으로 바꿨습니다. 결재에는 **본문·결재선 보기 / 원본 DB 기록 / 첨부** 링크와 현재·과거 자료 구분을 표시하며, 자료 종류에서 현재 문서·과거 기록을 골라 검색할 수 있습니다. 메일에는 보낸 사람·받는 사람·일시, **본문 보기 / 원본 MBOX / 첨부** 링크가 함께 표시됩니다. 상단에는 대상 ID·서버·백업 시각, 하단에는 수집 범위·검증 내역·보고서 링크를 표시합니다. 기존 탭·메일함 분류·검색·100건 페이지 이동·12px 글씨는 유지합니다.

이미 받은 백업은 **v0.4.6 → 보관함 열기 → 기존 백업 폴더 선택**으로 반영합니다. 메일 바로보기가 이미 준비된 경우 인덱스·분할 검색 자료·해시 목록만 갱신하며, 서버 연결·MBOX·첨부 읽기·원본 DB 변경은 하지 않습니다. 예전 메일 상태 파일에 첨부 이름이 없으면 보관된 첨부 파일명으로 표시하고 새 백업은 원래 표시 이름을 저장합니다. 별도로 만들어 둔 ZIP은 다시 만들어야 새 인덱스를 포함합니다. 갱신 후에는 프로그램을 종료하고 `index.html`만 열어도 같은 카드와 링크를 사용할 수 있습니다.

## 연결 확인과 메일 검사 (v0.4.5)

**v0.4.9 진행 표시:** 백업 화면에서 전체 단계 진행바와 현재 단계 진행바를 따로 표시하고, 전체·현재 단계 경과 시간을 `시:분:초`로 갱신합니다. SFTP는 전송량(GiB/MiB), 메일 바로보기는 완료 건수와 현재 메일의 본문·첨부 생성 용량, 인덱스는 처리한 기록 수, ZIP은 원본 기준 용량을 표시합니다. 서버 원본 검사에서는 파일 수·재시도도 보입니다. 전체 진행바는 작업 단계 수에 따른 표시이며 총 용량이나 남은 시간의 비율이 아닙니다. 총량을 알 수 없는 단계는 진행 중 애니메이션을 사용합니다. 중단·오류 시 시간과 처리량을 보존하고, 다음 작업부터 시간을 새로 셉니다. SSH 연결 확인·보관함 열기에도 적용되며 서버 도구를 다시 설치할 필요는 없습니다.

**SSH 연결 확인**은 서버 SSH 암호·개인키로 인증하고 SFTP 및 서버 Python 2.6 이상과 필수 모듈, DB 설정 파일 읽기·자료 폴더 읽기·psql 실행·임시 폴더 쓰기 권한을 확인합니다. 직원 ID와 메일을 선택하면 그 직원의 메일 경로 접근도 확인합니다. 추출 작업·서버 임시 폴더·직원 보관본을 생성하거나 DB 설정 내용을 출력하지 않습니다. PostgreSQL 인증과 실제 추출 범위는 **로그인하고 수집 시작**에서 검사합니다.

대용량 메일 검사 로그에 GiB 단위 진행량, 파일 수, 시도 횟수를 표시합니다. 준비 중 파일 추가·삭제·변경이 생기면 전체 목록을 최대 3회 대조하며 안정된 파일의 해시는 재사용합니다. 3회 안에 안정되지 않거나 전송 후 원본이 바뀌면 기존과 같이 완료를 거부합니다. 실제 메일 내용이 변경되는 시간에는 재시도 시간이 더 걸릴 수 있습니다. 첫 백업은 전체 MBOX이며 v0.4.18부터 기존 완료본이 있으면 15일 겹침 기간의 메일/결재를 병합합니다.

## 서버 지문 확인

CentOS 6의 오래된 `ssh-keygen`은 SHA-256 표시 옵션이 없을 수 있습니다. 서버 관리 콘솔에서 공개 호스트 키의 지문을 아래 명령으로 확인합니다. 개인키나 암호를 출력하지 않습니다.

```bash
python - <<'PY'
import base64, hashlib
parts = open('/etc/ssh/ssh_host_rsa_key.pub', 'rb').read().split()
key = base64.b64decode(parts[1])
fingerprint = base64.b64encode(hashlib.sha256(key).digest()).decode('ascii').rstrip('=')
print('SHA256:' + fingerprint)
PY
```

Windows가 표시한 SHA-256 지문과 일치하는지 확인합니다. 승인한 공개 지문은 Windows 사용자 폴더의 `.segio-archive/known_hosts`에 저장합니다. SSH 암호·개인키 내용·DB 암호는 Windows 설정·보관본에 저장하지 않습니다.

## 결재 문서 폴더 개수 제한 수정 (v0.4.21)

`결재 DB 추출 · OSError · errno=31 · render_bundle`는 결재 HTML/원본 JSON 저장 시 한 폴더 아래의 하위 폴더 개수 제한(EMLINK)에 걸린 오류입니다. 문서 번호와 과거 기록 번호의 해시를 이용한 256개 하위 경로로 분산해 저장합니다. 최종 `SSH-직원ID` 폴더와 인덱스 표시·검색 방식은 유지하며, 본문/첨부 링크와 선택 삭제도 새 경로를 지원합니다. 기존 백업 갱신 시 기존 경로와 새 경로를 함께 처리하고, 같은 문서의 옛 본문은 남기지 않으며 다른 문서가 참조하는 공유 첨부는 보존합니다.

새 프로그램에서 같은 직원 ID와 저장 상위 폴더로 수집을 다시 시작하세요. 서버 도구는 SSH로 자동 전송하므로 재설치가 필요 없습니다. 원본 DB·메일은 변경하지 않습니다. **이전 전송 이어받기**는 요청대로 기본 체크 해제이며 필요할 때 직접 선택합니다.

## 자료가 많은 계정의 결재 DB 조회 보완 (v0.4.19)

결재 DB 조회가 약 1분 후 실패하는 경우를 줄이기 위해, 같은 직원의 대상 문서 목록을 반복 계산하던 SQL을 PostgreSQL 8.4의 WITH 공통 테이블 식으로 쿼리마다 한 번 계산하도록 바꿨습니다. 백업 연결의 문장별 제한 시간을 60초에서 300초로 조정합니다. SERIALIZABLE READ ONLY, 개인 관계 필터, 조회 건수 대조는 유지하고 운영 DB 설정·인증·인덱스는 변경하지 않습니다. 기존 실패 작업은 같은 직원/저장 상위 폴더에서 이어받으면 새 도구로 다시 추출합니다.

실패 시 SQLSTATE·조회 단계(counts 또는 고정 테이블명)·psql 종료 코드만 안전한 진단에 남깁니다. 한국어 오류 접두어도 인식하며 DB 메모리/처리 한도와 문자 인코딩 오류를 구분합니다. SQL·문서·ID·경로·DB 암호와 원문 오류는 표시하지 않습니다. 5분 제한에서도 실패하면 새 오류 창의 SQLSTATE와 query 항목만 알려주세요. 원본 데이터를 바꾸거나 손상된 DB 기록을 조용히 제외하지 않습니다.

## 직원 폴더·15일 추가 백업·중단 자료 복구 (v0.4.18)

Windows 저장 폴더는 **상위 폴더**를 선택합니다. 직원 ID 입력란에 `koro`를 넣으면 최종 경로는 **`C:/Users/Owner/Documents/SEGIO보관함/SSH-koro/index.html`**입니다. `SSH-`는 프로그램이 폴더명에 붙입니다. 첫 수집도 이 직원 폴더에 진행하고, 추가 백업도 같은 폴더를 갱신합니다. 숫자 작업번호/contents 안에 최종 보관함을 만들지 않습니다. `.segio-ssh-cache`는 Windows 숨김 작업 관리 폴더이며 작업도 ID별로 구분합니다. 완료 팝업 후 직원 폴더의 index.html을 여세요.

- **중단된 수집 복구:** 기존 백업 갱신 → 예전 `.segio-ssh-cache/숫자/contents` 또는 현재 `SSH-직원ID` 폴더 선택. 원본이 모두 내려받아졌다면 서버 재접속 없이 해시를 검사하고 메일·검색 생성을 이어갑니다. 완료한 메일 페이지를 재사용하고 결과를 상위 폴더의 `SSH-직원ID`로 옮깁니다. 덜 받은 원본은 **이전 전송 이어받기**를 직접 체크하고 SSH 암호를 입력한 뒤 수집 시작으로 이어받습니다. 기존 캐시는 수동 삭제하지 마세요.
- **완료본에 자료 추가:** 기존 백업 갱신 → 완료된 직원 폴더 선택. 직원 ID/저장 상위 폴더를 자동 설정합니다. SSH 암호/키가 입력돼 있으면 시작하고, 없으면 암호 입력 후 수집 시작을 누릅니다. 같은 ID로 수집 시작을 직접 눌러도 이전 완료본을 찾아 추가 백업합니다. 화면 갱신만 하려면 보관함 열기를 사용합니다.
- **기간:** 마지막 완료일의 한국 시간 자정에서 15일 전부터 다시 가져옵니다. 결재는 DB 기안일자(wdate), 메일은 Date 또는 Received 중 기준일 이후 날짜가 있으면 포함합니다. 메일 날짜를 판단할 수 없으면 누락 방지를 위해 포함합니다. 첫 백업/처음 선택하는 종류는 전체 수집하며, 결재·메일 완료일은 별도로 기록합니다. 오래 전에 기안한 결재의 후속 수정은 기안일 기준 기간 추출의 범위에 들지 않습니다.
- **병합:** 기존 결재·메일은 보존하고 같은 결재 ID는 새 자료로 갱신합니다. 같은 메일함의 메시지 내용 SHA-256(끝의 구분 개행 정규화)과 중복 개수를 대조해 겹치는 15일 메일을 중복 추가하지 않습니다. 기존 메일 ID/완료 페이지를 유지합니다. 서버에서는 MBOX 헤더를 조사하고 선택한 원본 바이트 범위만 SFTP로 전송합니다. 추가 메일은 원본 EML로 보관하여 기존 50GB MBOX를 다시 복사/전송하지 않습니다. 서버의 MBOX를 읽어 조사하는 시간과 최초 기존 자료 해시 확인 시간은 필요합니다.

병합 보고서·요약·수집 건수도 새 자료에 맞춰 갱신하고, 이전 누락 파일 확인 사항을 함께 보존합니다. 하드링크를 지원하지 않는 드라이브에서는 안전한 별도 사본을 위한 추가 공간이 필요합니다.

병합은 별도 작업 위치에서 준비하고 완료본을 교체합니다. 원본 DB·MBOX는 수정하지 않으며 중단 시 기존 완료본을 유지합니다. 이전 `segio-ssh-직원ID` 완료본도 찾아 병합한 뒤 `SSH-직원ID`로 전환합니다. 서버 재설치는 필요 없습니다. 로컬 복구로 남은 서버 정리는 다음 동일 서버/SSH 계정 접속에서 재시도합니다. ZIP을 선택하면 `SSH-직원ID.zip`도 갱신합니다.

## 잘못 닫힌 이미지 태그로 인한 HTML 변환 오류 수정 (v0.4.17)

메일 바로보기의 safe_html에서 이미 제거된 하위 태그를 다시 unwrap하여 ValueError가 발생하는 문제를 수정했습니다. 잘못 중첩된 이미지 태그는 이미지 요소만 제거하고 주변 본문은 유지합니다. 표의 잘못된 숫자 속성도 안전하게 처리합니다. HTML을 해석하지 못하는 경우에는 해당 본문을 실행되지 않는 텍스트로 표시하고 damaged_html 내역을 남긴 뒤 다음 메일로 진행합니다. 스크립트·이벤트 속성·외부 이미지는 계속 차단합니다.

같은 Windows 저장 상위 폴더·직원 ID로 **이전 전송 이어받기**를 사용하세요. 이미 전송한 원본과 완료된 메일 페이지의 state.json을 확인해 재사용합니다. 캐시는 삭제하지 마세요. 서버 재설치는 필요 없습니다.

## 메일 손상·보안 차단 제외 처리 (v0.4.16)

메일 바로보기 생성 중 Base64·MIME 구조가 손상된 부분이나 Windows가 백신 차단/격리(오류 225·226)로 보고한 첨부를 제외하고 다음 자료를 처리합니다. 정상 본문·첨부는 계속 만들고 손상된 메일도 목록에서 확인할 수 있도록 안내 페이지를 만듭니다. MBOX/EML 원본은 변경하지 않으며 백신 설정 변경·차단 파일 재시도·검사 우회는 하지 않습니다. 완료 화면에는 제외 건수를, 해당 메일에는 제외 안내를 표시하고 **mail/render-issues.json**에 메일 식별자·부분 번호·분류만 기록합니다. 제외가 있으면 일반 완료 대신 확인 안내 팝업을 표시합니다.

**같은 Windows 저장 상위 폴더·직원 ID와 이전 전송 이어받기**를 사용하세요. 이미 받은 원본과 생성 완료한 메일의 state.json을 확인해 재사용합니다. 서버 재설치는 필요 없습니다. 기존 `.segio-ssh-cache`는 유지하세요.

저장 공간 부족·일반 권한 거부·원본 해시/크기 불일치·장치 오류는 제외하지 않고 중단합니다. 알려지지 않은 변환 오류도 메일 순번·식별자·예외 종류·함수 위치를 **mail/render-failure.json**과 오류 창에 표시합니다. 암호·제목·본문·파일명·예외 원문은 진단에 넣지 않습니다. 이 파일은 재개 후 정상 완료하면 제거됩니다. 파일 손상 전체를 자동 복구하거나 백신 판정을 대신하는 기능은 아닙니다.

## 전송 후 검증 오류와 버전 확인 (v0.4.15)

첨부가 많은 작업의 approval-check.json이 64KB를 넘으면 다운로드가 끝난 뒤 검증에서 invalid_metadata가 발생하고 종전 화면은 export_failed로 표시했습니다. 생성된 검증 목록의 크기 제한을 해제했으며 원본의 파일 정보·SHA-256 검증은 유지합니다. 기존 Windows 저장 상위 폴더·직원 ID를 그대로 입력하고 **이전 전송 이어받기**를 유지하면 ready 작업의 검증 도구를 원자적으로 갱신하고 이미 받은 파일을 검사해 재사용합니다. 5.92GB를 받았다면 캐시·서버 임시 작업을 수동 삭제하지 마세요. 서버 상태가 failed일 때만 기존 규칙에 따라 새 추출을 시작합니다.

SSH 오류에는 코드·단계·안전한 예외 종류/함수/줄 번호를 표시하고 서버 작업 폴더에 last-failure.json을 남깁니다. 진단에는 암호·문서·메일·예외 원문을 넣지 않습니다. 기존의 웹 전용 last_failure 안내는 SSH 오류에 사용하지 않습니다.

새 폴더·선택 ZIP의 기본 이름은 **SSH-직원ID**이며 추가 백업은 기존 내용과 병합합니다. EXE 속성의 **파일 버전/제품 버전**과 동봉 **VERSION.txt**에서 버전을 확인합니다. VERSION.txt에는 빌드 커밋과 UTC 빌드 시각이 있고 최종 백업 manifest.json에는 collector_version이 들어갑니다. 배포 ZIP은 한 번만 풀면 됩니다.

## 서버 작업 폴더와 완료 후 정리 (v0.4.14)

서버 작업 폴더 입력란의 기본값은 `/backup`입니다. 작업마다 `/backup/.segio-ssh-임의작업번호`를 0700으로 생성하고 로그에 경로를 표시합니다. 상위 폴더가 없으면 생성하고, 기존 상위 폴더의 권한은 그대로 둡니다. 서버 Python으로 쓰기 권한·최소 작업 공간을 확인합니다. `/tmp` 전체가 1GB인 서버에서 DB 중간 결과가 차는 문제를 피하기 위한 변경입니다. `--work-base /다른/작업경로`도 지원합니다. 이전 `/tmp` 작업이 정상 진행 중이면 그대로 이어받고, 실패 상태면 `/backup`에 새 추출을 시작합니다.

결재 첨부는 원본의 바이트·SHA-256·파일 정보를 기록한 뒤 MBOX처럼 직접 SFTP 전송합니다. 서버에 메일·첨부 사본이나 ZIP을 만들지 않습니다. DB 추출 결과와 HTML 등 메타데이터 공간은 필요하며, PostgreSQL 저장 디스크가 가득 차 있으면 원인을 별도로 해결해야 합니다.

Windows 폴더로 최종 저장한 뒤 해당 작업과 이 재시도에 연결된 실패 작업만 삭제하고 서버에서 사라졌는지 확인합니다. `server_cleanup.state=confirmed`로 기록합니다. 정리 실패는 Windows 백업을 보존하고 `pending`으로 표시합니다. `.segio-ssh-cache/cleanup-*.json`의 확인 기록을 이용해 다음 동일 서버·SSH 계정 접속에서 일부 삭제된 작업도 다시 정리합니다. 이미 없어진 작업은 완료로 처리하며, 무관한 작업·다른 진행 작업·원본 DB·메일·첨부는 삭제하지 않습니다. 완료된 백업 폴더와 캐시의 정리 확인 기록을 함께 유지해야 자동 재시도를 할 수 있습니다. ZIP 내부 manifest는 ZIP 생성 시점의 자료이며 정리 결과는 최종 Windows 폴더의 manifest에서 확인합니다.

## 40GB 이상 메일 처리

- **서버:** 결재 DB·첨부의 개인 보관본과 메일 목록·해시만 임시 저장합니다. MBOX 전체 복사본이나 전송 ZIP을 서버에 추가로 만들지 않습니다. 메일은 원본 파일을 SFTP로 직접 내려받습니다. 해시 계산 때문에 서버 디스크를 읽는 시간은 필요합니다.
- **Windows:** 원본 메일·검색 SQLite 외에 메일 본문 HTML과 해제한 첨부도 저장합니다. 입력·출력을 나누어 처리하며 전체 MBOX를 메모리에 올리지 않습니다. 검색 결과는 100건씩 표시합니다.
- **이어받기:** 기본으로 선택돼 있습니다. 같은 서버·SSH 계정·직원·선택 항목·저장 위치로 다시 시작하면 동일한 서버 추출 작업에서 이미 받은 파일과 부분 파일을 확인해 이어받습니다. 완료 파일과 이어받은 파일 모두 SHA-256을 검사합니다.
- **중단:** Windows의 `.segio-ssh-cache`를 보존합니다. 암호는 들어 있지 않지만 미완성 직원 자료가 포함되므로 저장 폴더 권한을 관리합니다. 이어받으려면 이 폴더를 유지합니다.
- **ZIP:** 기본 해제돼 있습니다. 필요하면 **ZIP도 생성**을 선택합니다. ZIP64를 지원하지만 ZIP 크기만큼 추가 디스크 공간과 압축 시간이 필요합니다. 폴더와 ZIP의 기본 이름은 `SSH-koro`이며 검증한 추가 자료를 병합한 뒤 갱신합니다.

원본 메일 40GB라면 Windows에는 40GB에 바로보기 HTML·해제한 첨부·결재 자료·검색 DB·여유 공간을 더한 용량이 필요합니다. ZIP을 함께 만들면 그만큼 추가로 확보합니다. 실제 40GB 운영 자료를 이 개발 환경에서 검증한 상태는 아니며, 전송 속도는 서버 디스크·네트워크에 따라 달라집니다.

복사 중 메일이 추가·삭제·변경되면 완성으로 처리하지 않습니다. 변경이 적은 시간에 재시도하며 이전 스냅샷이 더 이상 맞지 않을 때는 **이전 전송 이어받기**를 해제해 새로 추출합니다. 새 추출은 해당 선택의 미완성 Windows 캐시를 교체합니다. 서버의 이전 비공개 임시 작업은 남을 수 있습니다. 정상 완료 작업은 프로그램이 정리하며, 연결 종료·서버 재시작으로 임시 작업이 사라진 경우 새 추출이 필요합니다.

원본 MBOX/RFC822 파일과 기타 일반 파일을 모두 보존합니다. 표준 형식의 UTF-8·EUC-KR·CP949 제목을 색인하며, 인식되지 않는 고유 파일은 원본으로 보존하고 건수를 표시합니다. 첨부는 MIME 부분별 스트리밍으로 해제해 개별 메일이 32 MiB를 넘어도 읽습니다. 전체 MBOX도 `mail/raw`에 남습니다.

현재 전송 원본 파일 수는 20만 개, 전송 목록은 64 MiB로 제한합니다. MBOX 안의 메일 건수와 개별 원본 파일 크기에 같은 제한을 두지는 않습니다. 원본 파일이 매우 많은 계정은 목록 크기와 개수를 먼저 확인해야 합니다.

## 보관 범위

`cell_000`에서 지정 ID의 기안·결재선·대결·참조·자동회람·개인 수신 관계로 연결되는 결재와 관련 이력을 읽기 전용 스냅샷으로 추출합니다. 부서 권한만으로 보이는 문서·별도 확장 업무는 현재 범위에 포함하지 않습니다. 개인 기록 추출 범위이며 전체 PostgreSQL DB의 복제본은 아닙니다.

서버 기본 경로는 다음과 같습니다.

```text
DB 설정: /home/segio/cell000/etc/db.conf
직원 메일: /home/segio/cell000/home/{initial}/{user}/mbox
SSH 임시 작업: /backup/.segio-ssh-임의작업번호
```

본문·첨부·원본 메일과 누락 여부를 대조한 뒤 계정 삭제를 결정합니다. 보관본에는 `account_deletion_verified=false`가 유지되며, 이 프로그램은 계정이나 서버 자료를 삭제하지 않습니다.

## 명령행 실행

Python 소스로 실행하는 경우:

```bash
python -m segio_archive collect-ssh --host 192.168.0.100 --port 22 \
  --ssh-user root --user koro --output archives
```

SSH 암호는 실행 후 숨김 입력합니다. `--key-file`은 개인키 경로, `--zip`은 추가 ZIP, `--fresh`는 새 추출입니다. 서버 경로가 다르면 `--db-config`, `--cell`, `--mail-template`를 지정합니다. 암호를 명령행 인수에 넣지 않습니다.
