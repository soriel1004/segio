# 그룹웨어 문서 및 메일 백업 및 검색

**두 프로그램 공용 tools:** 이 SSH 백업 프로그램과 `segio-web`의 개인 로그인 프로그램에 같은 도구 묶음을 사용할 수 있습니다. [공용 tools 적용 안내](tools/README.md)를 참고하세요.

Windows에서 **서버 관리자 SSH 계정**으로 접속해 지정 직원의 결재 DB 자료와 MBOX 전체를 백업하고, 서버 연결 없이 검색·열람합니다. **v0.4.3부터 Windows 화면은 SSH로 고정**이며 서버 웹페이지·PHP·직원 로그인 창을 사용하지 않습니다.

서버 기본값은 **192.168.0.100 / 포트 22 / SSH 계정 root**입니다. SSH 암호와 백업할 직원의 SEGIO ID는 별도 항목입니다. 이 방식은 관리자가 직원 자료를 백업하는 도구이며 직원 SEGIO 암호를 검증하지 않습니다.

**[Windows v0.4.30 직접 다운로드](https://github.com/soriel1004/segio/actions/runs/42795918258/artifacts/13755401367)** (GitHub 로그인 필요). [최종 Actions #82](https://github.com/soriel1004/segio/actions/runs/42795918258)에서 Linux·Windows 시험과 실행 파일 빌드가 통과했습니다.

## Windows에서 실행

1. GitHub Actions의 최신 **성공한 v0.4.30 이상** 실행에서 `SEGIOArchive-Windows`를 받습니다. GitHub 로그인이 필요합니다. 다운로드한 ZIP을 **한 번만 풀면** `SEGIOArchive.exe`가 바로 나옵니다. `_internal`, `tools`를 포함한 폴더 전체를 유지합니다.
2. `SEGIOArchive.exe`를 실행하면 SSH 입력 화면이 바로 표시됩니다. 가져오기 방식을 선택할 필요가 없습니다.
3. SSH 서버 `192.168.0.100`, 포트 `22`, 계정 `root`, **서버 SSH 암호**, 백업할 직원의 **SEGIO ID**, Windows 저장 위치를 입력합니다. 개인키 인증도 지원합니다.
4. 먼저 **SSH 연결 확인**으로 접속·파일 접근을 확인할 수 있습니다. 직원 ID 없이도 SSH 연결은 검사하며, ID를 입력하면 메일 경로도 확인합니다. **로그인하고 수집 시작**을 누르고 처음 접속하는 서버의 공개 지문을 확인합니다. 지문 확인 방법은 [SSH 안내](docs/SSH_ARCHIVE.md)에 있습니다.
5. 수집 후 백업 폴더의 **index.html**을 열어 결재·메일을 검색하고 본문·첨부를 확인합니다.

서버에 웹 연결 기능을 설치할 필요가 없습니다. 프로그램이 고정 추출 도구를 SSH로 비공개 임시 폴더에 올려 실행합니다. 기존 Python 2.6·psql·DB 설정을 사용하며 DB 암호·인증·원본 파일 권한을 변경하지 않습니다. 서버 관리자 암호·개인키 내용·DB 암호는 Windows 보관본에 저장하지 않습니다.

## 서버 쓰기 대기로 추출이 중단되는 경우 (v0.4.30)

`server_io_pressure`가 발생하던 서버 전체 Dirty 쓰기량의 30초 제한을 생성 파일의 속도 조절로 바꿨습니다. 대기가 높으면 최대 1 MiB/s로 낮추고, 생성 파일만 조금씩 디스크에 반영합니다. 화면에서 부하 조절·디스크 반영 상태와 생성량을 확인할 수 있습니다. 실제 디스크 오류·공간 부족·메모리 부족과 원본 검증 실패는 계속 중단합니다. 새 Windows 프로그램이 SSH 도구를 자동 전송하므로 서버 재설치는 필요 없습니다. 기존 백업·캐시는 유지하세요.

다시 실행할 때는 같은 직원 ID·Windows 저장 상위 폴더에서 **이전 전송 이어받기**를 체크하세요. 준비가 끝난 작업은 재사용하고, 서버 추출이 실패한 작업은 새 작업 공간에서 다시 추출합니다. 기존 백업과 캐시는 유지합니다.

## 긴 전송 중 새 메일이 추가되는 경우 (v0.4.29)

서버 준비가 끝난 뒤 MBOX에 새 메일이 붙으면 파일 크기 비교에서 `SSH_SOURCE_CHANGED`로 중단되던 구간을 보완합니다. 준비 당시의 바이트 범위와 SHA-256을 고정하고 해당 범위까지만 내려받습니다. 같은 원본 파일의 크기 증가를 허용하되 받은 모든 파일·구간의 크기·SHA-256이 일치해야 완료합니다. 파일 축소·교체·삭제·같은 크기의 수정·새 원본 파일 생성·MBOX가 아닌 파일의 변경은 계속 중단하며, 복사 중 기존 범위가 달라져 해시가 불일치하면 완료하지 않습니다. 준비 단계의 원본 해시 검사는 그대로 유지합니다.

**이번처럼 SFTP 중단 후 이어받기:** 새 EXE에서 **같은 직원 ID·Windows 저장 상위 폴더 → 이전 전송 이어받기 직접 체크 → 수집 시작**으로 진행합니다. 기존 `SSH-직원ID`와 `.segio-ssh-cache`를 유지하세요. ready 상태의 서버 작업은 검증 도구만 갱신하고 DB를 다시 추출하지 않으며 받은 파일을 SHA-256으로 확인해 재사용합니다. 실제 원본이 교체·축소·수정된 경우에는 이어받기를 해제하고 새로 추출해야 합니다.

**보관 범위는 준비 당시까지입니다.** 그 뒤 도착한 메일은 다음 추가 백업으로 가져옵니다. 확인된 MBOX 증가량은 로그·인덱스 경고·manifest coverage에 표시하고 계정 삭제 검증 완료로 처리하지 않습니다. 추가 백업은 원본 기준 시점과 완료일 중 더 이른 시점의 15일 전부터 시작해 오래된 작업을 이어받았을 때의 누락을 막습니다. 완료 시각 표시는 유지합니다. 서버 MBOX 사본·ZIP을 만들거나 메일 서비스·원본 권한을 변경하지 않습니다.

## Windows 공유 폴더의 DB 연결 오류 수정 (v0.4.28)

`\\서버\공유\SSH-직원ID` 같은 UNC 경로를 `Path.as_uri()`로 변환하면 SQLite 기본 빌드가 서버 이름을 URI authority로 해석해 `SQLITE_ERROR(1): invalid uri authority`로 거부합니다. 바로보기 첫 건 전에 `portable_mail.build_portable_mail:349`에서 실패하던 구간입니다. UNC 서버·공유 이름을 파일 경로에 보존하는 SQLite URI로 바꾸고 **읽기 전용 연결**을 유지합니다. 메일 바로보기·검색·메일 원본 조회·검색 화면 생성·삭제 확인/준비·DB 정리의 7곳을 함께 적용했습니다. 로컬 드라이브 경로와 한글·공백·`#`·`%`의 인코딩도 보존합니다.

**이미 공유 폴더에 전송을 완료했다면:** 새 프로그램의 **기존 백업 갱신 → 해당 공유 폴더의 `SSH-직원ID` 선택**으로 받은 원본을 검증하고 메일·검색 생성을 다시 진행합니다. 같은 공유 폴더를 그대로 사용하며 서버에서 다시 받을 필요가 없습니다. 기존 백업과 `.segio-ssh-cache`는 유지합니다. 추가 백업은 실패한 작업의 `incoming`/`merged` 폴더를 선택합니다.

## 바로보기 준비 오류 진단과 자동 절전 방지 (v0.4.27)

메일 첫 건을 처리하기 전의 DB 열기·조회 오류도 `processing-failure.json`으로 저장하고 팝업·로그에 저장 경로를 표시합니다. 예외 종류·실패 함수/줄·errno/winerror·SQLite 오류 번호·진행 건수만 기록하며 암호·메일 제목·본문·원래 예외 메시지는 넣지 않습니다. SQLite 오류, 메모리 부족, Windows 파일 처리 오류를 구분합니다. 원본과 완료 페이지는 보존합니다. 기존 개별 메일 오류는 `mail/render-failure.json`, SFTP 오류는 직원 캐시의 `transfer-failure.json`에 기록됩니다. 해당 단계에서 오류가 없으면 그 파일은 없습니다.

**전송 100% 후 바로보기 준비에서 실패한 작업:** 새 프로그램의 **기존 백업 갱신 → `SSH-직원ID` 폴더 선택**으로 받은 원본을 검증하고 로컬 처리를 다시 시도합니다. 추가 백업의 작업이면 팝업·로그에 표시된 `incoming`/`merged` 폴더를 선택합니다. 폴더와 `.segio-ssh-cache`는 유지하며 서버 재설치는 필요 없습니다. 같은 오류가 나면 팝업에 표시된 `processing-failure.json`만 확인합니다. 사진에 나온 실제 원인은 진단 결과로 확인해야 합니다.

Windows GUI의 수집·기존 백업 갱신 중에만 스레드의 자동 절전 방지를 요청하고 작업 종료·취소·실패 시 해제합니다. 화면보호기·화면 꺼짐·잠금은 유지하며 시스템 전원 설정은 바꾸지 않습니다. 사용자가 직접 절전·최대 절전·종료하는 것까지 막지는 않습니다.

## SHA-256 불일치 파일 자동 재수신 (v0.4.26)

이어받은 부분 파일의 앞부분이 손상되면 끝까지 받아도 해시가 일치하지 않습니다. v0.4.26은 서버 원본이 바뀌지 않았는지 먼저 확인한 뒤 **불일치한 파일만 처음부터 최대 2회 순차 재수신**합니다. 검증을 통과한 다른 파일은 유지하고 서버 DB 추출 작업을 새로 만들지 않습니다. 재수신 후에도 크기·SHA-256이 같아야 완료합니다. 반복 불일치나 원본 변경은 중단하며 진단 파일에 파일 순번·전송량·이어받기 시작 위치·불일치 횟수를 기록합니다.

**기존 오류 작업 복구:** 같은 직원 ID·Windows 저장 상위 폴더를 입력하고 **이전 전송 이어받기**를 직접 체크하세요. 기존 `SSH-직원ID`와 `.segio-ssh-cache`는 유지하며 서버 재설치는 필요 없습니다. 해당 파일이 큰 MBOX라면 그 파일 전체를 다시 받는 시간은 필요합니다. 운영 자료의 실제 손상 원인을 사진만으로 확정한 것은 아닙니다.

## SFTP 중단 자동 복구와 오류 구분 (v0.4.25)

전송 중 연결·원격 읽기 오류는 최대 3회 재연결합니다. 서버 지문과 같은 추출 작업의 원본 상태를 확인한 뒤 받은 위치부터 이어가며, 재연결 후에는 순차 읽기로 전환합니다. 1 MiB 이하 파일도 순차 읽기를 사용해 작은 파일마다 사전 읽기 스레드를 만들지 않습니다. 파일 크기·SHA-256 검증은 유지합니다.

Windows 디스크 부족·파일 잠금·접근 거부·보안 차단과 서버 파일 오류를 별도 코드로 표시합니다. 실패하면 직원 캐시의 `transfer-failure.json`에 작업 종류·오류 번호·전송 바이트·재시도 횟수를 기록하며 파일명·문서 내용·암호·원래 예외 메시지는 넣지 않습니다. SSH 암호는 전송 재연결에 필요한 동안 메모리에만 유지하고 원본 검증 후 해제합니다.

**이미 99% 받은 작업:** 같은 직원 ID와 Windows 저장 상위 폴더를 입력하고 **이전 전송 이어받기**를 직접 체크한 뒤 시작하세요. 기존 `SSH-직원ID`와 `.segio-ssh-cache`를 삭제하지 마세요. 기본 체크 해제는 유지하며 서버 재설치는 필요 없습니다. 서버 원본이 변경된 작업은 완료 처리하지 않습니다.

운영 오류의 정확한 원인은 종전 메시지만으로 확정하지 못했습니다. 합성 자료의 99% 연결 단절·이어받기를 시험하며 실제 40~50GB 운영 자료 전체의 재실행 결과는 별도 확인이 필요합니다.

## 최종 파일 목록 생성의 메모리 오류 수정 (v0.4.24)

`server_memory_limit · MemoryError · run_export:1016`은 문서 변환 뒤 전체 파일 목록을 임시 인덱스 JSON으로 다시 합치던 위치입니다. SSH용 임시 HTML에는 Windows 인덱스 생성 대기 안내만 기록합니다. 최종 검색 화면은 기존대로 Windows에서 만듭니다.

파일 목록·원본 참조·검증 기록·확인 사항·전송 목록을 서버 작업 폴더의 임시 SQLite로 관리하고 JSON을 순서대로 기록합니다. 기존 목록을 다시 통째로 읽거나 딕셔너리/문자열 사본을 만드는 처리를 제거했습니다. 최종 목록을 저장하는 동안에도 연결·중단 요청을 확인하며 화면에 **파일 목록·검증 정보 순차 저장 중**으로 표시합니다. 임시 SQLite는 준비 작업이 끝나면 정리하며 원본 DB·메일은 변경하지 않습니다.

합성 문서 31,000건·파생 파일 62,000개의 최종 manifest/검증/전송 목록 생성을 128 MiB 제한 및 실제 Python 2.6에서 확인합니다. 실제 운영 계정 50GB 전체를 시험한 결과는 아닙니다. 서버의 기존 메모리/디스크 부하 제한은 유지합니다.

새 ZIP 전체를 새 폴더에 풀어 `tools` 폴더를 포함한 채 실행하세요. 같은 직원 ID와 Windows 저장 상위 폴더로 수집을 다시 시작하면 실패 작업을 새 도구로 다시 생성합니다. 서버 재설치는 필요 없습니다.

## 결재 관련 기록 직렬화의 메모리 한도 오류 수정 (v0.4.23)

`server_memory_limit · MemoryError · iter_render_bundle:785`에서 원본 JSON을 하나의 큰 문자열로 만들던 부분을 수정했습니다. 문서에 연결된 현재/과거 결재선·기타 기록을 SQLite에서 한 행씩 읽고, 원본 JSON과 결재 HTML을 작은 조각으로 기록합니다. 결재선 정렬도 디스크 인덱스를 사용합니다. 회원·서식·첨부 조회와 문서 ID 확인도 필요한 항목만 조회하고, 이미지 캐시에는 키와 값의 크기를 함께 계산합니다. 진단에 매우 긴 이미지 주소는 원문 대신 SHA-256을 남기며 실제 DB 원본 값은 그대로 보관합니다.

서버 메모리 제한을 높이거나 기록을 제외하지 않습니다. 큰 관련 기록·서명을 가진 현재/과거 문서의 생성과 정렬·원본 값·구간 해시를 128 MiB 제한 및 실제 Python 2.6에서도 검사합니다. 계정의 50GB 전체 용량을 메모리에 올리지 않습니다. Windows 저장 공간은 원본 MBOX 외에 바로보기 본문/첨부·검색 색인·갱신용 공간도 필요합니다.

새 프로그램에서 같은 직원 ID와 저장 상위 폴더로 수집을 다시 시작하세요. 실패한 서버 추출 작업은 새 도구로 다시 생성합니다. 서버 재설치는 필요 없습니다.

## 서버 부하 완화·대량 자료 삭제·행 강조 (v0.4.22)

SSH 결재 추출은 원본 기록 전체를 메모리에 보관하지 않고 `/backup` 작업 공간의 임시 SQLite에서 문서별로 읽습니다. 문서 목록도 순서대로 기록하며 이미지 캐시를 제한합니다. 서버에는 문서별 작은 파일을 만들지 않고 한 개의 비압축 순차 파일에 기록하며, Windows에서 각 파일의 검증된 범위를 받아 원래 경로로 저장합니다. 이 임시 파일도 정상 완료 후 서버 작업 폴더와 함께 삭제합니다. 서버 추출기와 그 자식 psql 클라이언트에 CPU nice +10, 지원 시 idle I/O 우선순위를 적용합니다. 추출기 주소 공간은 물리 메모리의 1/8과 512 MiB 중 작은 값(최소 96 MiB)으로 제한하며, 운영 PostgreSQL 데몬이나 SEGIO의 우선순위·메모리 설정은 변경하지 않습니다. DB 세션 work_mem은 1 MiB, 문장별 제한은 5분, 전체 조회 대기는 15분입니다. 서버의 기본 Python sqlite3 모듈이 필요합니다.

결재 변환은 최대 초당 20건, 생성 파일 쓰기는 최대 8 MiB/s로 제한합니다. Linux의 아직 디스크에 반영하지 않은 쓰기량(Dirty)이 64 MiB를 넘으면 생성 파일 쓰기를 최대 1 MiB/s로 낮추고, 낮아지면 원래 속도로 돌아옵니다. 서버 전체 쓰기 대기가 30초 넘게 유지된다는 이유만으로 실패 처리하지 않습니다. 생성 파일은 4 MiB 이상 쓸 때마다 해당 파일만 디스크에 반영하며, 화면에 부하 조절·디스크 반영 상태를 표시합니다. 실제 쓰기 오류·공간 부족·메모리 부족은 계속 중단합니다. 같은 서버 작업 상위 폴더에서는 추출 한 개만 실행합니다. Windows와 2분 이상 연결이 유지되지 않거나 중단을 요청하면 추출기와 실행 중인 psql 클라이언트를 중단합니다. DB 백엔드에는 기존 문장별 제한도 적용됩니다. 디스크/RAID/커널 문제로 서버가 멈추는 것까지 프로그램만으로 방지한다고 보장하지 않습니다.

인덱스는 제목 밑줄 대신 행 전체 음영을 사용하고 삭제 버튼을 검색 버튼 오른쪽에 표시합니다. 폴더 확인 후 체크박스부터 표시하며 큰 검색 DB는 삭제 대상을 선택한 뒤 읽습니다. 파일 목록 확인과 DB 읽기 진행을 표시하고, 선택한 폴더를 기억하지 못하더라도 선택 화면은 계속 사용할 수 있습니다.

새 검색 DB에는 결재 분류에 필요한 요약만 넣고 전체 원본 JSON은 문서 폴더에 그대로 보관합니다. **이미 완료한 큰 백업은 새 Windows 프로그램의 보관함 열기에서 직원 폴더를 한 번 선택하세요.** 64 MiB 이상의 기존 DB를 순서대로 정리하고 인덱스를 갱신합니다. 원본 문서·첨부·MBOX를 다시 내려받거나 바꾸지 않습니다. 중간 실패 시 기존 DB/manifest로 복구합니다. 그 뒤 프로그램을 닫고 같은 폴더의 index.html만 열어 삭제할 수 있습니다. 정리 후에도 검색 DB가 512 MiB를 넘는 예외적인 백업은 브라우저 메모리 한도로 직접 삭제가 제한됩니다.

## 결재 문서 폴더 개수 제한 수정 (v0.4.21)

`결재 DB 추출 · OSError · errno=31 · render_bundle`는 결재 HTML/원본 JSON 저장 시 한 폴더 아래의 하위 폴더 개수 제한(EMLINK)에 걸린 오류입니다. 문서 번호와 과거 기록 번호의 해시를 이용한 256개 하위 경로로 분산해 저장합니다. 최종 `SSH-직원ID` 폴더와 인덱스 표시·검색 방식은 유지하며, 본문/첨부 링크와 선택 삭제도 새 경로를 지원합니다. 기존 백업 갱신 시 기존 경로와 새 경로를 함께 처리하고, 같은 문서의 옛 본문은 남기지 않으며 다른 문서가 참조하는 공유 첨부는 보존합니다.

새 프로그램에서 같은 직원 ID와 저장 상위 폴더로 수집을 다시 시작하세요. 서버 도구는 SSH로 자동 전송하므로 재설치가 필요 없습니다. 원본 DB·메일은 변경하지 않습니다. **이전 전송 이어받기**는 요청대로 기본 체크 해제이며 필요할 때 직접 선택합니다.

## 자료가 많은 계정의 결재 DB 조회 보완 (v0.4.19)

결재 DB 조회가 약 1분 후 실패하는 경우를 줄이기 위해, 같은 직원의 대상 문서 목록을 반복 계산하던 SQL을 PostgreSQL 8.4의 WITH 공통 테이블 식으로 쿼리마다 한 번 계산하도록 바꿨습니다. 백업 연결의 문장별 제한 시간을 60초에서 300초로 조정합니다. SERIALIZABLE READ ONLY, 개인 관계 필터, 조회 건수 대조는 유지하고 운영 DB 설정·인증·인덱스는 변경하지 않습니다. 기존 실패 작업은 같은 직원/저장 상위 폴더에서 이어받으면 새 도구로 다시 추출합니다.

실패 시 SQLSTATE·조회 단계(counts 또는 고정 테이블명)·psql 종료 코드만 안전한 진단에 남깁니다. 한국어 오류 접두어도 인식하며 DB 메모리/처리 한도와 문자 인코딩 오류를 구분합니다. SQL·문서·ID·경로·DB 암호와 원문 오류는 표시하지 않습니다. 5분 제한에서도 실패하면 새 오류 창의 SQLSTATE와 query 항목만 알려주세요. 원본 데이터를 바꾸거나 손상된 DB 기록을 조용히 제외하지 않습니다.

## 직원 폴더·15일 추가 백업·중단 자료 복구 (v0.4.18)

Windows 저장 폴더는 **상위 폴더**를 선택합니다. 직원 ID 입력란에 `koro`를 넣으면 최종 경로는 **`C:/Users/Owner/Documents/SEGIO보관함/SSH-koro/index.html`**입니다. `SSH-`는 프로그램이 폴더명에 붙입니다. 첫 수집도 이 직원 폴더에 진행하고, 추가 백업도 같은 폴더를 갱신합니다. 숫자 작업번호/contents 안에 최종 보관함을 만들지 않습니다. `.segio-ssh-cache`는 Windows 숨김 작업 관리 폴더이며 작업도 ID별로 구분합니다. 완료 팝업 후 직원 폴더의 index.html을 여세요.

- **중단된 수집 복구:** 기존 백업 갱신 → 예전 `.segio-ssh-cache/숫자/contents` 또는 현재 `SSH-직원ID` 폴더 선택. 원본이 모두 내려받아졌다면 서버 재접속 없이 해시를 검사하고 메일·검색 생성을 이어갑니다. 완료한 메일 페이지를 재사용하고 결과를 상위 폴더의 `SSH-직원ID`로 옮깁니다. 덜 받은 원본은 **이전 전송 이어받기**를 직접 체크하고 SSH 암호를 입력한 뒤 수집 시작으로 이어받습니다. 기존 캐시는 수동 삭제하지 마세요.
- **완료본에 자료 추가:** 기존 백업 갱신 → 완료된 직원 폴더 선택. 직원 ID/저장 상위 폴더를 자동 설정합니다. SSH 암호/키가 입력돼 있으면 시작하고, 없으면 암호 입력 후 수집 시작을 누릅니다. 같은 ID로 수집 시작을 직접 눌러도 이전 완료본을 찾아 추가 백업합니다. 화면 갱신만 하려면 보관함 열기를 사용합니다.
- **기간:** 마지막 완료일의 한국 시간 자정에서 15일 전부터 다시 가져옵니다. 결재는 DB 기안일자(wdate), 메일은 Date 또는 Received 중 기준일 이후 날짜가 있으면 포함합니다. 메일 날짜를 판단할 수 없으면 누락 방지를 위해 포함합니다. 첫 백업/처음 선택하는 종류는 전체 수집하며, 결재·메일 완료일은 별도로 기록합니다. 오래 전에 기안한 결재의 후속 수정은 기안일 기준 기간 추출의 범위에 들지 않습니다.
- **병합:** 기존 결재·메일은 보존하고 같은 결재 ID는 새 자료로 갱신합니다. 같은 메일함의 메시지 내용 SHA-256(끝의 구분 개행 정규화)과 중복 개수를 대조해 겹치는 15일 메일을 중복 추가하지 않습니다. 기존 메일 ID/완료 페이지를 유지합니다. 서버에서는 MBOX 헤더를 조사하고 선택한 원본 바이트 범위만 SFTP로 전송합니다. 추가 메일은 원본 EML로 보관하여 기존 50GB MBOX를 다시 복사/전송하지 않습니다. 서버의 MBOX를 읽어 조사하는 시간과 최초 기존 자료 해시 확인 시간은 필요합니다.

병합 보고서·요약·수집 건수도 새 자료에 맞춰 갱신하고, 이전 누락 파일 확인 사항을 함께 보존합니다. 하드링크를 지원하지 않는 드라이브에서는 안전한 별도 사본을 위한 추가 공간이 필요합니다.

병합은 별도 작업 위치에서 준비하고 완료본을 교체합니다. 원본 DB·MBOX는 수정하지 않으며 중단 시 기존 완료본을 유지합니다. 이전 `segio-ssh-직원ID` 완료본도 찾아 병합한 뒤 `SSH-직원ID`로 전환합니다. 서버 재설치는 필요 없습니다. 로컬 복구로 남은 서버 정리는 다음 동일 서버/SSH 계정 접속에서 재시도합니다. ZIP을 선택하면 `SSH-직원ID.zip`도 갱신합니다.

## 잘못 닫힌 이미지 태그로 인한 HTML 변환 오류 수정 (v0.4.17)

메일 바로보기의 safe_html에서 이미 제거된 하위 태그를 다시 unwrap하여 ValueError가 발생하는 문제를 수정했습니다. 잘못 중첩된 이미지 태그는 이미지 요소만 제거하고 주변 본문은 유지합니다. 표의 잘못된 숫자 속성도 안전하게 처리합니다. HTML을 해석하지 못하는 경우에는 해당 본문을 실행되지 않는 텍스트로 표시하고 damaged_html 내역을 남긴 뒤 다음 메일로 진행합니다. 스크립트·이벤트 속성·외부 이미지는 계속 차단합니다.

같은 Windows 저장 상위 폴더·직원 ID로 **이전 전송 이어받기**를 사용하세요. 이미 전송한 원본과 완료된 메일 페이지의 state.json을 확인해 재사용합니다. 캐시는 삭제하지 마세요. 서버 재설치는 필요 없습니다.

## 메일 손상·보안 차단 제외 처리 (v0.4.16)

메일 바로보기 생성 중 Base64·MIME 구조가 손상된 부분이나 Windows가 백신 차단/격리(오류 225·226)로 보고한 첨부를 제외하고 다음 자료를 처리합니다. 정상 본문·첨부는 계속 만들고 손상된 메일도 목록에서 확인할 수 있도록 안내 페이지를 만듭니다. MBOX/EML 원본은 변경하지 않으며 백신 설정 변경·차단 파일 재시도·검사 우회는 하지 않습니다. 완료 화면에는 제외 건수를, 해당 메일에는 제외 안내를 표시하고 **mail/render-issues.json**에 메일 식별자·부분 번호·분류만 기록합니다. 제외가 있으면 일반 완료 대신 확인 안내 팝업을 표시합니다.

**같은 Windows 저장 상위 폴더·직원 ID와 이전 전송 이어받기**를 사용하세요. 이미 받은 원본과 생성 완료한 메일의 state.json을 확인해 재사용합니다. 서버 재설치는 필요 없습니다. 기존 `.segio-ssh-cache`는 유지하세요.

저장 공간 부족·일반 권한 거부·원본 해시/크기 불일치·장치 오류는 제외하지 않고 중단합니다. 알려지지 않은 변환 오류도 메일 순번·식별자·예외 종류·함수 위치를 **mail/render-failure.json**과 오류 창에 표시합니다. 암호·제목·본문·파일명·예외 원문은 진단에 넣지 않습니다. 이 파일은 재개 후 정상 완료하면 제거됩니다. 파일 손상 전체를 자동 복구하거나 백신 판정을 대신하는 기능은 아닙니다.

## v0.4.15 검증 오류·버전 관리·저장 폴더

첨부 검증 목록이 64KB를 넘을 때 서버 추출은 ready인데 전송 후 검증에서 export_failed로 표시되던 오류를 수정했습니다. 생성된 첨부·메일 검증 목록은 요청용 64KB 제한을 적용하지 않습니다. 이미 받은 데이터는 **같은 Windows 저장 상위 폴더·직원 ID와 이전 전송 이어받기 선택**으로 재사용합니다. ready 상태의 이전 서버 작업에서는 검증 도구만 안전하게 갱신하고 다시 추출하지 않습니다. 캐시나 서버 작업 폴더를 지우지 마세요. 검증은 원본 변경 여부를 계속 확인합니다.

SSH 오류는 원래 오류 코드·실패 단계·안전한 예외 종류/코드 위치를 표시합니다. 서버 작업의 last-failure.json에는 암호·ID·문서 내용·예외 원문 없이 진단 분류만 기록합니다. 웹용 last_failure 안내를 SSH 오류에 잘못 표시하던 것도 수정했습니다.

현재 Windows 백업은 **SSH-직원ID** 폴더에 저장합니다. 예: `D:/백업/SSH-koro/index.html`. 같은 직원의 다음 수집은 15일 겹침 구간을 병합해 같은 폴더를 갱신합니다. 이전 segio-ssh 이름은 v0.4.15~17 형식입니다.

프로그램 버전은 **EXE 우클릭 → 속성 → 자세히 → 파일 버전·제품 버전**, 동봉 **VERSION.txt**에서 확인합니다. VERSION.txt에는 빌드 커밋·UTC 빌드 시각도 들어갑니다. 새 백업 manifest.json에도 collector_version을 기록합니다. 표시·EXE 리소스·설치 메타데이터는 segio_archive.__version__을 공통 기준으로 사용합니다. 다운로드 ZIP을 한 번 푸는 배포 방식은 유지합니다.

## 서버 공간·50GB 이상 백업 (v0.4.14)

Windows 화면의 **서버 작업 폴더 기본값은 `/backup`**입니다. 실제 작업은 `/backup/.segio-ssh-작업번호`에 만들고 로그에 경로를 표시합니다. 기존 `/tmp`의 실패 작업은 이어받기 상태를 확인한 뒤 새 작업 경로에서 다시 추출하며, 성공 후 해당 실패 작업도 정리합니다. CLI는 `--work-base /backup`으로 지정합니다. `/backup` 상위 폴더가 없으면 SSH 실행 계정으로 생성하며 기존 폴더의 권한은 변경하지 않습니다.

**메일 MBOX와 결재 첨부 원본은 서버에 복사하거나 압축하지 않고 SFTP로 직접 전송**합니다. 작업 폴더에는 DB 결과·문서 화면·검증 목록만 저장합니다. DB 쿼리 중간 자료에는 여유 공간이 필요하며 PostgreSQL 자체 디스크 부족은 별도 조치가 필요합니다. 원본이 바뀌면 검증을 중단하고 완료로 처리하지 않습니다. Windows에서 1 MiB 단위로 받아 50GB를 한꺼번에 메모리에 올리지 않습니다.

Windows에 검증된 백업 폴더를 저장한 뒤 **현재 서버 작업 폴더의 삭제와 부재를 확인**합니다. 정리가 실패하거나 일부만 삭제되면 PC의 `.segio-ssh-cache/cleanup-*.json`에 재시도 기록을 남기고, 동일 서버·SSH 계정의 다음 백업 접속 때 다시 정리합니다. `manifest.json`의 `server_cleanup.state`는 `confirmed` 또는 `pending`입니다. 무관한 작업·서버 원본 DB·메일·첨부는 지우지 않습니다. 실패·중단 중인 전송은 재시도할 수 있도록 유지하며, 다운로드 완료와 정리를 확인하기 전 캐시 폴더를 수동 삭제하지 마세요. 서버 설치는 필요 없습니다.

## index.html에서 직접 삭제 (v0.4.13)

새 백업에는 자동 적용됩니다. **이미 백업한 폴더는 새 Windows 프로그램의 보관함 열기에서 한 번 선택**해 인덱스를 갱신하세요. 서버 접속·자료 재수집은 필요 없습니다. 이후 프로그램을 종료해도 됩니다.

1. **최신 Chrome 또는 Edge로 백업 폴더의 index.html을 직접 엽니다.** 페이지당 표시 오른쪽의 **삭제**를 누릅니다. 처음에는 현재 `index.html`이 들어 있는 백업 폴더를 선택하고 브라우저의 파일 수정 권한을 허용합니다. 다른 백업 폴더를 선택하면 삭제하지 않습니다. 브라우저가 권한을 유지한 경우 다음 작업에는 폴더 선택을 생략합니다.
2. 목록 번호 앞에 나타난 체크 상자로 결재·메일을 선택합니다. **선택한 자료 삭제 → 대상·건수·임시 공간 확인 → 백업본에서 삭제**를 누릅니다. **선택 취소**는 원래 목록으로 돌아갑니다. 기존 보관함 열기도 계속 지원합니다.
3. 본문·첨부·DB 기록과 MBOX 내부 해당 메일을 실제 제거하고 목록·검색·건수·해시를 갱신합니다. 공유 첨부·남은 메일은 보존합니다. **서버 원본과 별도 ZIP은 변경하지 않습니다.** 완료된 삭제는 되돌릴 수 없습니다.

삭제 중 진행률·경과 시간·중단을 표시하며 최종 적용 단계에는 중단할 수 없습니다. 브라우저 탭을 유지하세요. 오류·중단 때는 기존 자료를 복원합니다. 비정상 종료 후에는 **동일한 index.html → 삭제 → 백업 폴더 선택**으로 복구하고 화면을 다시 불러옵니다. `.segio-browser-edit` 작업 폴더를 수동 삭제하지 마세요. Windows 프로그램에서 시작한 삭제의 복구 폴더는 기존 `.segio-edit`입니다.

브라우저는 MBOX를 1 MiB 단위로 읽고 남은 메시지의 원래 바이트를 유지합니다. 원본을 덮어쓰기 전에 복구용 사본을 저장하므로 **대용량 메일은 시간과 여유 공간이 필요**합니다. 확인 창은 해당 MBOX의 복구 사본·새 파일·브라우저 임시 파일 등을 포함한 보수적인 공간 상한을 표시합니다. 브라우저는 선택한 디스크의 실제 여유 공간을 조회할 수 없으며 부족하면 복구 후 안내합니다. 검색 SQLite 메타데이터가 512 MiB를 넘는 보관함은 Windows 프로그램에서 삭제합니다. MBOX 전체 용량을 메모리에 올리지 않습니다.

`viewer`, `search`, `mail`, `documents` 등 백업 폴더 전체를 함께 보관하세요. Firefox·Safari 등 폴더 수정 API를 지원하지 않는 브라우저는 조회·검색만 제공합니다. CLI 관리 화면은 `python -m segio_archive view "백업폴더" --edit`로 엽니다.

## 최신 날짜순·페이지당 표시 건수 (v0.4.10)

전체·결재·메일 목록은 **기안일자 또는 메일 헤더 날짜가 최신인 자료부터** 표시합니다. 시간대가 다른 메일도 실제 시각을 비교하며 같은 시각이면 원래 기록 순서를 유지합니다. 날짜가 없거나 해석되지 않는 자료는 마지막에 표시하고 백업 시각으로 대신 채우지 않습니다. 시간대가 없는 날짜는 정렬할 때 한국 시간(KST)을 기준으로 합니다. 화면의 메일 날짜·시간대 표시는 유지합니다.

목록 위 **페이지당 표시**에서 **25·50·75·100건**을 선택하거나 **직접 입력**란에 **1~1,000건**을 넣고 **적용** 또는 Enter를 누릅니다. 기본값은 100건입니다. 건수를 바꾸면 첫 페이지로 돌아가며 검색·분류를 전환해도 선택한 건수를 유지합니다. 새로고침 시에도 URL에 보존된 표시 건수와 분류를 복원합니다.

새 백업에는 자동 적용됩니다. **이미 백업했다면 v0.4.10 → 보관함 열기 → 백업 폴더 선택**으로 적용하세요. 이미 메일 바로보기가 준비된 백업은 서버 재접속·자료 재수집·원본 MBOX·첨부 읽기 없이 인덱스만 갱신합니다. 원본 자료와 SQLite는 유지하며, 기존 ZIP은 갱신하지 않습니다.

## 백업 진행바·경과 시간 (v0.4.9)

Windows 화면에 **전체 단계 진행바**, **현재 단계 진행바**, **전체 경과 시간·현재 단계 경과 시간**을 표시합니다. 전체 진행은 완료한 단계 수를 기준으로 하고, 현재 진행은 SFTP의 전송 바이트·검색 색인의 원본 바이트·메일 바로보기 건수·인덱스 기록 수·선택 ZIP의 원본 바이트를 기준으로 표시합니다. 서버 메일 검사에서는 검사 용량·파일 수·재시도 횟수를 표시합니다. DB 추출처럼 총량이 아직 없는 작업은 진행 중 표시로 안내합니다.

메일 본문·첨부를 생성하는 동안에는 현재 메일의 생성 용량도 표시하며, 큰 파일을 검사하는 동안에도 경과 시간은 계속 갱신됩니다. 중단·오류 시에는 진행률과 시간을 보존하고 완료 전에는 전체 진행바를 100%로 표시하지 않습니다. 새 작업을 시작하면 시간이 초기화됩니다. SSH 연결 확인과 보관함 열기에도 동일한 표시를 제공합니다. 서버 도구 재설치는 필요 없으며 기존 인덱스 화면과 ‘백업 완료하였습니다.’ 팝업은 유지합니다.

## 사진과 같은 표 목록·범위 검색 (v0.4.8)

인덱스는 **전체 / 결재 / 메일** 탭과 건수, 검색 범위 선택창·검색어·검색 버튼, **번호 / 제목 / 자료 구분·메일함 / 기안일자·메일 헤더 날짜** 열로 구성합니다. 처음에는 전체 목록을 보여주고 100건씩 표시합니다. 기본 글씨는 12px입니다. 제목을 누르면 기존 본문을 바로 엽니다.

결재 탭은 **전체 결재 / 완료문서 / 반려문서 / 참조문서 / 수신문서 / 진행문서 / 임시문서 / 상태 미확인**, 메일 탭은 실제 받은·보낸·지운편지함과 사용자 보관함으로 분류합니다. 선택한 분류 안에서 제목·주소·결재 내용을 검색하며 검색 범위 선택창과 탭이 함께 전환됩니다. 참조·수신은 다른 상태 분류와 겹칠 수 있습니다. 확인되지 않은 상태는 임의로 완료 처리하지 않습니다. 사진의 건수를 고정하지 않고 실제 백업 자료로 계산합니다.

기안일자는 보관된 DB의 `wdate`를 한국 시간(KST)으로 표시하고, 메일 날짜는 원래 헤더의 시간대를 유지합니다. 날짜가 없으면 ‘미기록’이며 백업 시각으로 대신 채우지 않습니다. DB 원본·첨부 버튼은 목록 아래 **현재 목록의 원본·첨부 바로가기**, 수집 정보·현재/과거 필터는 **수집 범위·검증 내역 및 추가 옵션**에서 펼칠 수 있습니다.

**기존 백업은 v0.4.8의 ‘보관함 열기’에서 백업 폴더를 선택하세요.** 메일 바로보기가 준비된 백업은 서버 재접속 없이 DB 메타데이터로 인덱스만 갱신합니다. 원본 MBOX·첨부·본문·SQLite는 유지하며 별도의 기존 ZIP은 변경하지 않습니다. 새 백업은 자동 적용합니다. 완료 팝업은 ‘백업 완료하였습니다.’를 유지합니다.

## 최신 SSH 백업 (v0.4.5)

저장소의 최신 공용 추출 도구를 포함합니다. **SSH 연결 확인**은 SSH 로그인·SFTP, 서버 Python과 필수 모듈, DB 설정·자료·메일 경로 접근, psql 실행 권한을 검사합니다. 서버에 추출 작업이나 직원 자료를 만들지 않으며, DB 실제 접속은 수집 시작 때 검사합니다.

메일 원본 검사 중 용량·파일 수·재시도 횟수를 로그에 표시합니다. 검사 중 파일이 새로 들어오거나 변경되면 최대 3회 다시 확인하고, 그대로인 파일의 SHA-256 결과는 재사용합니다. 계속 바뀌는 원본이나 전송 후 변경은 완료로 처리하지 않습니다. 서버에 전체 MBOX 복사본이나 ZIP을 만들지 않고 SFTP로 직접 전송합니다. 중단한 동일 작업의 이어받기도 유지합니다.

## 기존 보관함과 같은 카드형 표시 (v0.4.6)

저장소의 기존 `archive.INDEX`와 `tools/db_archive_index.html`에서 제공하던 **본문·결재선 보기 / 원본 DB 기록 / 첨부** 버튼을 SSH 백업 인덱스에도 표시합니다. 현재 문서·과거 기록 구분과 필터, 대상 ID·서버·백업 시각, 수집 범위·검증 내역과 보고서 링크를 복원했습니다. 메일에는 보낸 사람·받는 사람·일시, 본문·원본 MBOX·첨부 링크를 표시합니다. 결재·메일 탭, 받은·보낸편지함과 사용자 보관함, 검색·100건 페이지 이동, 기본 12px 글씨는 유지합니다.

**기존 백업은 v0.4.6의 ‘보관함 열기’에서 백업 폴더를 한 번 선택하면 됩니다.** 이미 메일 바로보기가 준비된 백업은 서버 재접속·다운로드·MBOX 재분석 없이 저장된 메타데이터로 인덱스만 갱신합니다. SQLite·원본 MBOX·본문·첨부 바이트는 유지합니다. 오래된 메일 상태 파일에는 첨부 표시 이름이 없으므로 그 경우 저장된 첨부 파일명을 표시합니다. 별도로 보관한 기존 ZIP은 변경하지 않습니다.

v0.4.7의 백업 완료 팝업은 **“백업 완료하였습니다.”**입니다. 새 백업은 이 저장소의 `segio_archive/search_page.py`에 있는 인덱스 템플릿을 그대로 사용하고 백업별 데이터만 채웁니다. v0.4.6의 화면·검색·본문·첨부 표시를 유지하므로, 이미 v0.4.6으로 갱신한 인덱스를 다시 만들 필요는 없습니다.

## index.html에서 결재·메일 바로보기 (v0.4.2)

첫 화면에서 **결재 / 메일 탭**, 각 건수와 백업 목록을 표시합니다. **검색** 버튼 또는 Enter로 검색하고 **전체 목록**으로 돌아갑니다. 기본 글씨는 **12px**, 목록은 100건씩 표시합니다.

**기존 백업은 v0.4.2 프로그램의 ‘보관함 열기’에서 해당 폴더를 한 번 선택하세요.** 서버 접속·재전송 없이 이미 받은 MBOX에서 메일 본문 HTML과 첨부를 생성합니다. 완료 후에는 프로그램을 종료하고 **백업 폴더의 `index.html`만 실행**해 결재·메일 본문·첨부를 열 수 있습니다. 새 백업은 수집 중 자동으로 준비합니다. [자세한 갱신 안내](docs/SSH_ARCHIVE.md#목록검색-화면과-기존-백업-갱신-v042)

메일 바로보기용 HTML·첨부가 추가되므로 Windows 저장 공간을 더 확보하세요. 중단 후 다시 갱신하면 해시가 일치하는 완료 메일을 재사용합니다. 별도로 만든 기존 ZIP은 갱신하지 않습니다.

## 받은편지함·보낸편지함·편지 보관함 (v0.4.4)

`index.html`의 **메일** 탭에서 **전체 메일 / 받은편지함 / 보낸편지함**과 메일함별 건수를 표시합니다. 사용자 지정 분류는 **편지 보관함** 아래에 원래 이름과 하위 경로로 따로 표시합니다. 메일 목록의 **메일함** 열에서도 소속을 확인할 수 있습니다. 메일함을 고른 상태에서 제목·주소로 검색하면 선택한 메일함 안에서 찾습니다. **전체 목록**은 검색어와 메일함 선택을 초기화합니다.

기존 백업은 **v0.4.4 프로그램 → 보관함 열기 → 백업 폴더 선택**으로 적용합니다. 이미 본문 바로보기가 준비된 v0.4.2/0.4.3 백업은 원본 MBOX·첨부·검색 DB를 변경하지 않고 분류와 인덱스만 갱신합니다. 서버에서 다시 받지 않습니다.

분류는 `mail/sources.json`에 보존한 실제 메일함 경로를 기준으로 합니다. 보낸 사람 주소로 임의 재분류하지 않습니다. 받은·보낸 외의 기본함과 빈 보관함도 수집된 원본에 있으면 표시합니다. 별도 표시 이름이 원본에 남아 있지 않으면 저장 경로 이름을 사용하고, 메일함을 알 수 없는 개별 EML은 **분류 미확인**으로 표시합니다.

## 대용량 메일과 이어받기

- 서버에 MBOX 전체 복사본이나 전송 ZIP을 추가로 만들지 않고 **SFTP로 원본을 직접 전송**합니다. 서버 임시 공간에는 결재 보관본과 메일 목록·해시만 저장합니다.
- Windows 화면의 **이전 전송 이어받기**는 기본 체크 해제입니다. 직접 체크하면 이어받기를 사용합니다. 같은 서버·직원·저장 위치로 다시 시작하면 동일한 스냅샷의 부분 파일부터 이어받고 SHA-256을 검사합니다.
- 메일은 SQLite에 제목·헤더·원본 위치를 색인하고, 바로보기용 HTML과 첨부를 별도로 저장합니다. MBOX·첨부는 나누어 읽으며 검색 목록은 100건씩 표시합니다.
- **ZIP도 생성**은 선택 사항이며 기본 해제돼 있습니다. 선택하면 ZIP64로 추가 보관본을 만들며 그만큼 디스크 공간과 시간이 더 필요합니다.
- 서버 메일이 전송 중 변경되면 완료로 처리하지 않습니다. 변경이 적은 시간에 다시 시도하거나 이어받기를 해제해 새 스냅샷을 만듭니다.

40GB 원본이면 Windows에 원본 40GB와 바로보기 HTML·추출한 첨부·결재 자료·검색 DB·여유 공간이 필요합니다. 실제 40GB 운영 자료는 별도 현장 시험이 필요합니다. 속도는 서버 디스크와 네트워크에 따라 달라집니다.

## 보관되는 자료

```text
segio-ssh-koro/
  index.html                   검색·열람 시작 화면
  search/part-*.js             파일 직접 열기용 분할 검색 자료
  catalog.sqlite3              검색 DB·결재 원본 기록·메일 위치
  catalog.json                 결재 목록
  manifest.json                범위·건수·파일 SHA-256
  documents/.../               결재 HTML·DB 원래 값·첨부
  mail/raw/...                 MBOX·EML·기타 파일 원본
  mail/offline/.../index.html   메일 본문 바로보기
  mail/offline/.../attachments/ 메일 첨부·본문 이미지
  mail/sources.json            원래 이름·경로·파일 해시 대응
```

폴더 전체를 함께 보관합니다. 바로보기 준비 후에는 `index.html`만 열면 되며 프로그램·서버 연결 없이 메일을 읽습니다. 한글 본문, 표, CID 본문 이미지, 첨부를 표시하고 외부 추적 이미지·실행 스크립트는 제외합니다. 32 MiB를 넘는 메일도 본문·첨부를 나누어 처리합니다. 각 텍스트 부분이 8 MiB를 초과하면 처음 8 MiB와 제한 안내를 표시하며 전체 내용은 원본 MBOX에 보존됩니다. 인식하지 못하는 고유 원본 파일은 원본을 보존하고 건수를 표시합니다.

결재는 지정 ID의 기안·결재선·대결·참조·자동회람·개인 수신 관계와 관련 이력을 읽기 전용 스냅샷으로 조회합니다. 부서 권한만으로 열리는 문서·별도 확장 업무는 현재 범위에 포함하지 않습니다. 전체 PostgreSQL DB 복제본은 아니며, 실제 화면별 접근 권한과 동일하다고 검증한 기능은 아닙니다.

**파일 무결성 검증**은 보관 파일의 SHA-256을 검사합니다. 대표 결재·메일·첨부와 누락 여부를 대조한 뒤 계정 삭제를 결정해야 합니다. `account_deletion_verified=false`가 유지되며 이 프로그램은 계정이나 원본 자료를 삭제하지 않습니다.

## 명령행과 기존 방식

```bash
python -m segio_archive collect-ssh --host 192.168.0.100 --port 22 --ssh-user root --user koro --output archives
python -m segio_archive view archives/segio-ssh-koro
python -m segio_archive verify archives/segio-ssh-koro
```

SSH 암호는 실행 후 숨김 입력합니다. `--key-file`, `--zip`, `--fresh`, `--no-mail`, `--no-approvals`를 지원합니다. 서버 경로 옵션은 [SSH 안내](docs/SSH_ARCHIVE.md)를 보세요. 경고가 있는 정상 수집은 종료 코드 2이며 받은 자료는 보관됩니다.

이전 직원 웹 로그인 방식은 **DB·MBOX 바로 가져오기**, 화면 수집은 **웹 화면 수집**으로 남아 있습니다. 이전 설치·오류 진단은 [웹 연결 안내](docs/WINDOWS_LOGIN.md), 관리자 CLI 추출은 [DB 보관 안내](docs/DB_ARCHIVE.md), DB 구조 확인은 [DB 진단 안내](docs/DB_EXPORT.md)를 보세요. SSH 기본 방식은 이 웹 연결 도구를 사용하지 않습니다.

## 개발·검증

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
SEGIO_TEST_PHP=php .venv/bin/python tools/run_ci_tests.py
```

GitHub Actions는 Linux·Windows에서 시험한 뒤 Windows EXE를 빌드합니다. `build_windows.ps1`로 Windows에서 직접 빌드할 수 있습니다. 합성 자료의 실제 SSH/SFTP 서버에서 백업·이어받기·지문 확인·메일 원본·제목 검색·본문·첨부를 검사합니다. 실제 Python 2.6.9와 임시 PostgreSQL 16.2에서도 SSH 서버 추출기를 검증했습니다. 자세한 결과와 한계는 [VALIDATION.md](VALIDATION.md)에 기록합니다.

사용자의 실제 CentOS 서버 SSH 접속·40GB 자료 추출과 Windows EXE 현장 실행은 별도 확인이 필요합니다. 업로드된 SEGIO의 인코딩 소스·실행 파일은 배포물에 포함하지 않습니다. 운영 암호·개인키·문서·메일을 채팅에 보내지 마세요.
